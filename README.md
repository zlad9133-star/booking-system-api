# Mawidy — منصة حجز المواعيد

منصة عربية متجاوبة لحجز المواعيد وإدارة الخدمات، مبنية باستخدام Node.js وExpress وMongoDB وواجهة RTL.

## الوظائف الحالية
- إنشاء حساب وتسجيل الدخول باستخدام JWT.
- كلمات المرور مخزنة باستخدام bcrypt.
- عرض الخدمات وإضافة/تعديل الخدمات بصلاحية المدير.
- إنشاء الحجوزات وعرض حجوزات العميل وإلغاؤها.
- لوحة مدير مرئية لعرض الحجوزات وتغيير حالتها وإضافة الخدمات.
- منع تكرار حجز الخدمة في التاريخ والوقت نفسيهما للحجوزات النشطة عبر فهرس MongoDB فريد.
- رسائل عربية للأخطاء وحالات التحميل والنجاح.
- حماية أساسية عبر Helmet وCORS ومحدد طلبات والتحقق من البيانات.
- الواجهة الأمامية تُقدّم من تطبيق Express نفسه داخل مجلد `public`.

## التشغيل المحلي
1. استخدم Node.js 20 أو أحدث.
2. نفّذ `npm install`.
3. انسخ `.env.example` إلى `.env` وأدخل إعدادات MongoDB وقيمة JWT سرية طويلة.
4. اضبط بيانات المدير في متغيرات البيئة.
5. نفّذ `npm run seed` لإنشاء حساب المدير والخدمات التجريبية.
6. نفّذ `npm run dev` وافتح `http://localhost:3000`.

## إعدادات البيئة
- `MONGO_URI`: رابط اتصال MongoDB.
- `JWT_SECRET`: قيمة عشوائية طويلة وسرية.
- `PORT`: منفذ الخادم (تحدده منصة الاستضافة غالباً).
- `CLIENT_URL`: أصل الواجهة المسموح به عند استضافة الواجهة على نطاق منفصل. عند تقديم الواجهة من نفس الخادم لا يلزم ضبطه.
- `ADMIN_NAME`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`: بيانات حساب المدير الذي ينشئه أمر seed.

لا ترفع ملف `.env` إلى GitHub ولا تضع الأسرار في ملفات الواجهة الأمامية.

## API
| Method | Endpoint | Access |
|---|---|---|
| GET | /api/health | عام |
| POST | /api/auth/register | عام |
| POST | /api/auth/login | عام |
| GET | /api/auth/me | مسجل |
| GET | /api/services | عام |
| POST | /api/services | مدير |
| PATCH | /api/services/:id | مدير |
| POST | /api/bookings | عميل |
| GET | /api/bookings/mine | عميل |
| PATCH | /api/bookings/:id/cancel | صاحب الحجز |
| GET | /api/admin/bookings | مدير |
| PATCH | /api/admin/bookings/:id/status | مدير |

أرسل التوكن في الهيدر: `Authorization: Bearer TOKEN`.

## النشر على Render
يوجد ملف `render.yaml` لإعداد خدمة Web Service:
1. أنشئ قاعدة MongoDB Atlas واضبط Network Access وDatabase User وفق إعدادات آمنة.
2. اربط المستودع في Render واختر Blueprint أو Web Service باستخدام إعدادات `render.yaml`.
3. أدخل `MONGO_URI` وبيانات المدير في Environment الخاصة بالخدمة. ينشئ Render قيمة `JWT_SECRET` تلقائياً من ملف Blueprint.
4. بعد اكتمال النشر، شغّل `npm run seed` مرة واحدة من Shell في Render لإنشاء المدير والخدمات التجريبية.
5. تحقق من `/api/health` وأن قيمة `database` هي `connected`، ثم اختبر التسجيل والحجز ولوحة المدير من رابط الخدمة.

## حالة التحقق
تمت إضافة ملفات الواجهة وإعداد نشر مبدئي إلى المستودع. لم يتم في هذه المرحلة ربط MongoDB فعلياً أو تشغيل اختبارات تكامل على قاعدة بيانات، ولم يتم إنشاء خدمة استضافة أو التحقق من رابط عام. لذلك لا تعتبر الحجوزات أو الاتصال العام جاهزين قبل إتمام خطوات الإعداد والاختبار أعلاه.
